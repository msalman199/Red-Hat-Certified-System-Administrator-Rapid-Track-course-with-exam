# Installing and Managing Software Packages

A comprehensive lab guide designed to master package management systems on enterprise Linux distributions. You will learn to manipulate packages using `dnf`, `yum`, and `rpm`, handle group software environments, interrogate package metadata repositories, and handle active lifecycle dependencies.

---

## 🎯 Objectives
By the end of this lab, you will be able to:
* **Install** software packages using `dnf` and `yum` package managers.
* **Query** and search for installed components using `rpm` and `dnf` commands.
* **Remove** unwanted software payloads from the core operating system cleanly.
* **Update** target packages and systemic repositories safely to stable versions.
* **Understand** structural functional differences across high-level and low-level tools.
* **Navigate** complex package dependencies and isolate library version conflicts.
* **Verify** software asset signature integrity and installation state maps.

## 🚀 Lab Tasks

### Task 1: Installing Packages Using DNF and YUM

#### 1.1 Understanding Package Managers
* **`DNF` (Dandified YUM)**: The high-level tool handling dependencies on RHEL 8+ and modern Fedora.
* **`YUM` (Yellowdog Updater Modified)**: The legacy package workflow driver for vintage RHEL systems.
* **`RPM` (Red Hat Package Manager)**: The underlying lower-level tool driving file installation metrics.

#### 1.2 Checking Your Package Manager
```bash
# Check executable paths
which dnf
which yum

# Audit current runtime versions
dnf --version
# OR
yum --version
```

#### 1.3 Updating Package Repository Information
```bash
# Synchronize remote repository cache files
sudo dnf update
# OR for legacy enterprise setups
sudo yum update
```

#### 1.4 Installing Individual Packages
```bash
# 1. Deploy nano text editor environment
sudo dnf install nano -y
which nano
nano --version

# 2. Deploy htop resource performance monitor
sudo dnf install htop -y
htop --version

# 3. Deploy wget transport protocol downloader
sudo dnf install wget -y
wget --version
```

#### 1.5 Installing Multiple Packages at Once
```bash
# Consolidate installations in a single process thread
sudo dnf install tree unzip zip curl -y

# Verify parallel deployments quickly
tree --version
unzip -v | head -1
zip -v | head -1
curl --version | head -1
```

#### 1.6 Installing Package Groups
```bash
# Survey group software category mappings
dnf group list

# Install development compiler toolchains completely
sudo dnf group install "Development Tools" -y

# Verify compilation framework tool access
gcc --version
```

### Task 2: Querying Installed Packages with RPM and DNF

#### 2.1 Using RPM to Query Packages
```bash
# Enumerate all installed platform assets
rpm -qa | head -20

# Evaluate total deployment metrics
rpm -qa | wc -l

# Confirm target presence
rpm -q nano

# Dissect detailed package metadata blocks
rpm -qi nano

# Track concrete file locations generated by a package
rpm -ql nano | head -10

# Map a system file path back to its parent package source
rpm -qf /usr/bin/nano
```

#### 2.2 Using DNF to Query Packages
```bash
# Search across names and descriptive text string metrics
dnf search editor

# Check explicit tracking status details
dnf list nano

# Pull full ledger profiles of active system applications
dnf list installed | head -20

# View dynamic package lifecycle data summaries
dnf info nano

# Track out a package's structural dependency tree maps
dnf deplist nano

# Audit pending package updates across open repositories
dnf check-update
```

#### 2.3 Advanced Package Queries
```bash
# Determine which application delivers an absolute system path
dnf provides /usr/bin/python3

# Identify capabilities matching generic glob expressions
dnf provides "*/bin/gcc"

# Review historic transactional operations ledger
dnf history list | head -10

# List all operational source mirrors
dnf repolist

# Check total configuration records (enabled and disabled targets)
dnf repolist all

# Filter items exclusive to external software pools (e.g., EPEL)
dnf repository-packages epel list 2>/dev/null | head -20
```

### Task 3: Removing and Updating Packages

#### 3.1 Removing Individual Packages
```bash
# Remove a target element isolated from dependent chains
sudo dnf remove tree -y
which tree

# Track package dependency configurations securely
sudo dnf install httpd -y
dnf deplist httpd

# Erase the element along with its contextual branches
sudo dnf remove httpd -y

# Sweep leftover dependencies away automatically
sudo dnf autoremove -y
```

#### 3.2 Updating Packages
```bash
# Identify tracking versions
rpm -q kernel

# Upgrade isolated software elements manually
sudo dnf update nano -y
dnf info nano

# Check full systems and sync upgrade steps
dnf check-update
sudo dnf update -y
dnf history list | head -5
```

#### 3.3 Downgrading and Reinstalling Packages
```bash
# Re-extract fresh package metadata fields over broken binaries
sudo dnf reinstall nano -y

# Audit available version histories
dnf list nano --showduplicates

# Roll back code states to historical version records (example schema)
# sudo dnf downgrade nano-2.9.8-1.el8
```

#### 3.4 Managing Package Cache
```bash
# Track active storage space allocations
du -sh /var/cache/dnf/

# Evacuate stale runtime artifacts and indexes
sudo dnf clean all

# Re-verify systemic file layout footprints
du -sh /var/cache/dnf/
```

### 💻 Practical Exercise: Web Environment Scenario

```bash
# Step 1: Deploy a complete runtime stack
sudo dnf install httpd php php-mysql mariadb-server git -y

# Step 2: Validate database and application binaries layout
rpm -q httpd php php-mysql mariadb-server git

sudo systemctl disable httpd
sudo dnf remove httpd php php-mysql mariadb-server -y
sudo dnf autoremove -y
```

## 🛠️ Troubleshooting

### Issue 1: Package Not Found
* Re-synchronize local software indexes with your source mirrors: `sudo dnf update`.
* Search for name variations using partial keywords: `dnf search keyword`.
* Confirm required parent source lines are enabled: `dnf repolist`.

### Issue 2: Dependency Conflicts
* Force the engine to resolve best-match parameters using destructive replacement options:
  ```bash
  sudo dnf install package_name --best --allowerasing
  ```
* Tell the processor to skip broken code links temporarily:
  ```bash
  sudo dnf install package_name --skip-broken
  ```

### Issue 3: Disk Space Failures
* Audit available space across mounted filesystems: `df -h`.
* Flush the package manager's storage files: `sudo dnf clean all`.
* Strip out orphaned packages: `sudo dnf autoremove -y`.

---

## 🛡️ Best Practices
* **Use Dry-Runs Before Production Updates:** Run `dnf check-update` to preview modifications and avoid unexpected library shifts on live servers.
* **Leverage `dnf history` for Rollbacks:** Treat the package manager's transaction logs like version control. Use `dnf history undo <ID>` to revert broken package changes.
* **Keep Cache Layers Clean:** Clear the storage footprint with `dnf clean all` regularly to avoid cache mismatch bugs and free up disk space.
